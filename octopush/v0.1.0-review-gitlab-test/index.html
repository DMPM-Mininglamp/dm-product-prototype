OctoPush 登录与加入团队启动路径 PRD v0.1.0

1. 文档信息

  • 文档版本：v0.1.0
  • 创建日期：2026-04-27
  • 产品名称：OctoPush 登录与加入团队启动路径
  • 原型文件：octopush-prototype-v0.1.0-merged.html
  • 设计规范：/Users/ml/mininglamp/DMClaw/design/octopush-design-spec.html

1.1 布局原则

  • 登录前展示启动检查、统一登录和邀请链接中转。
  • 登录授权成功后，账号校验、默认团队校验、无团队加入、邀请拉起加入、工作区准备和准备失败都展示在登录页右侧校验面板内。
  • 只有团队工作区准备成功后，才进入 OctoPush 主界面；主界面不再承载团队选择或加入团队操作。
  • 各登录/校验状态页面沿用统一的左右分栏尺寸、边距、卡片宽度和视觉风格。
  • 客户端不展示“链接/码”双入口，邀请链接中的有效部分就是邀请码，客户端表单统一称为“邀请码”。
2

2. 启动恢复

2.1 目标

客户端启动后优先恢复本地登录态和默认团队上下文，不向用户展示团队选择。

2.2 正常流程

  1. 打开 OctoPush。
  2. 检查本地是否存在登录态。
  3. 校验 Access Token；如果过期则尝试 Refresh Token 静默刷新。
  4. 登录态有效后校验账号状态。
  5. 系统自动校验默认团队是否可进入。
  6. 默认团队可进入时，进入团队工作区准备流程。
  7. 没有可进入团队时，进入加入团队页。

2.3 页面要求

  • 页面标题展示“正在打开 OctoPush”。
  • 用步骤列表展示本地登录态、Access Token、默认团队上下文的检查状态。
  • 不展示团队列表，也不让用户手动选择团队。
  • 团队校验结果需要展示在登录页右侧校验面板内，不进入主界面后再处理团队选择或加入。
3

3. 统一账号登录

3.1 触发条件

  • 本地无登录态。
  • Refresh Token 已过期。
  • 账号状态异常，需要清除本地登录态后重新登录。
  • 被邀请链接拉起客户端，但当前未登录。

3.2 页面要求

  • 主按钮为“使用统一账号登录”。
  • 不展示本地账号密码输入框。
  • 如果是邀请链接拉起登录，登录完成后继续本次邀请码加入动作。
4

4. 等待授权

4.1 正常流程

  1. 用户点击“使用统一账号登录”。
  2. 客户端打开统一登录平台。
  3. 用户在外部页面完成登录与授权。
  4. 统一登录平台回调客户端。
  5. 客户端写入本地登录态并刷新账号状态。
  6. 有可进入团队时自动准备默认团队；没有团队时进入加入团队页。

4.2 页面要求

  • 展示“刷新登录状态”“重新登录”“退出”。
  • 回调失败时允许手动刷新登录状态。
5

5. 自动恢复默认团队

5.1 触发条件

  • 登录态有效。
  • 账号下存在可进入团队。
  • 本地存在默认团队或服务端可返回默认团队。

5.2 页面要求

  • 展示“正在恢复上次团队工作区”。
  • 系统自动进入默认团队，不展示团队选择页。
  • 展示团队状态校验和团队工作区准备进度。
6

6. 默认团队不可用

6.1 触发条件

默认团队不可访问，且系统没有可自动进入的其他团队。

6.2 页面要求

  • 标题为“无法进入默认团队”。
  • 说明 OctoPush 不提供团队选择。
  • 提供“重新检查”“加入团队”“退出当前账号”。
  • 不清除登录态。
7

7. 无可进入团队

7.1 触发条件

登录态有效，但账号没有任何可进入团队，或默认团队不可用且没有其他可自动进入团队。

7.2 页面要求

  • 标题为“你还没有加入任何团队”。
  • 展示邀请码输入框和“加入团队”按钮。
  • 展示联系 OctoPush 助理二维码。
  • 提供退出当前账号入口。
  • 不展示创建团队入口。
  • 不展示团队选择列表。
8

8. 邀请链接 Web 中转

8.1 触发条件

用户打开公开邀请链接，例如 https://octopush.ai/invite/ABCD1234。

8.2 页面要求

  • 页面尝试拉起 octopush://join-team?token=ABCD1234。
  • 如果客户端未自动打开，提供“打开 OctoPush”“下载 OctoPush”“复制邀请码”。
  • 点击“打开 OctoPush”后，客户端进入邀请拉起加入页，并在登录页右侧校验面板内展示本次邀请码加入信息。
9

9. 客户端被邀请拉起

9.1 正常流程

  1. 客户端通过邀请链接被拉起。
  2. 客户端从链接中解析出邀请码。
  3. 如果用户未登录，先进入统一账号登录。
  4. 登录完成后继续本次加入动作。
  5. 在登录页右侧校验面板内展示即将加入的团队信息。
  6. 用户点击“加入团队”。
  7. 校验通过后准备团队工作区。

9.2 设计规则

  • 邀请码是公开加入凭证，不绑定个人；邀请链接只是邀请码的承载形式。
  • 不展示“等待确认邀请”或 Pending Invite。
  • 可以展示“即将加入的团队信息”作为安全确认。
  • 凭证校验失败时展示失败原因，不消耗使用次数。
10

10. 准备团队工作区

10.1 触发条件

  • 系统自动恢复默认团队。
  • 用户通过邀请码成功加入团队。

10.2 准备内容

  1. 团队基础信息。
  2. 用户角色与权限。
  3. 团队配置。
  4. Agent 配置。
  5. 本地目录绑定。
  6. 本地缓存与索引。
  7. 同步任务状态。
  8. 模型网关配置。
  9. 最近工作上下文。
11

11. 准备失败

11.1 触发条件

团队配置、权限、本地环境或缓存加载失败。

11.2 页面要求

  • 标题为“无法进入该团队”。
  • 提供“重试”“返回加入团队”“退出当前账号”。
  • 失败时不清除登录态。
12

12. 主界面

12.1 目标

团队工作区准备成功后进入 OctoPush 主界面，继续沿用迭代前原型的 Claw 管理体验。

12.2 规则

  • 保留原型已有的侧边栏、我的 Claw、Claw 详情、创建 Claw、配置 Claw、联系我们、版本信息和退出登录能力。
  • 退出当前账号时必须清除 Access Token、Refresh Token、账号信息、默认团队上下文和临时加入状态。
13

13. 加入团队异常

13.1 校验规则

场景页面反馈是否消耗次数
邀请码有效加入团队成功是
邀请码无效邀请码无效，请检查后重试否
邀请码已过期该邀请已过期，请联系团队管理员否
使用次数已达上限该邀请已达到使用上限否
团队已停用该团队当前不可加入否
团队成员已满当前团队成员数量已达上限否
用户已在团队内你已加入该团队否
网络异常加入失败，请检查网络后重试否

13.2 原型覆盖

原型在无团队页和客户端邀请加入页提供加入失败反馈状态，用于评审错误文案和输入框布局。
